# quality-reviewer · SKILL

> 完整工作流细节见 `部虾创5个Agent详细配置.md` §3

---

## 流程概览

```
pipeline_read(draft_content, research_notes, article_idea)
  ↓
[Step 1] 读槽位 —— 加载所有需要审核的信息
  ↓
[Step 2] 四类检查 —— 事实核查 → 撞车检测 → 平台合规 → 写作质量
  ↓
[Step 3] 输出报告 —— pipeline_write_slot("review_feedback")
  ↓
[Step 4] 重审 —— content-writer 修改后仅检查 P0/P1 项
```

---

## Step 1 — 读槽位

### 必读资料

| 资料 | 工具 | 注意 |
|------|------|------|
| `draft_content` | `pipeline_read('draft_content')` | 审核对象——正文 + 写作说明 |
| `research_notes` | `pipeline_read('research_notes')` | 唯一的事实对照基准 |
| `article_idea` | `pipeline_read('article_idea')` | 用户原始意图 |
| 风格 DNA | `style_read_profile` | 检查写作是否改味 |
| 平台规则 | `memory_read('platform/{platform}/rules')`（旧名 kb_read）| 敏感词、字数限制、格式规范 |
| KB 快照 | `snapshot_read` | 了解当前系统知识状态 |
| session_note | `session_note_read` | 读 content-writer 的自述笔记 |

### 读前判断

- [ ] research_notes 是否存在？不存在 → 事实核查标注"无原始调研数据"
- [ ] 目标平台是什么？→ 加载对应平台规则
- [ ] 用户风格 DNA 是否有 HOT 硬规则？→ 重点检查

---

## Step 2 — 四类检查

### 2.1 事实核查（权重 35%）

逐句对比 `draft_content` 和 `research_notes`：

| 结果 | 严重度 | 处理 |
|------|--------|------|
| 数据点在 research_notes 中存在且引用正确 | 通过 | — |
| 数据点在 research_notes 中存在但引用有偏差 | P1 | 标注差异，建议修正 |
| 数据点在 research_notes 中不存在但可通过 web 验证 | P1→P0 | 用 `group:web` 搜索验证。找到则降为 P1，找不到则升级 P0 |
| 数据点在 research_notes 中不存在且无法验证 | P0 | 阻断，标注"凭空出现" |
| research_notes 完全为空 | — | 标注"无原始数据，纯文本审查" |

**事实核查的联网验证流程**：

```
发现未命中 research_notes 的数据
  ↓
用 group:web 搜索 2-3 组不同关键词验证
  ↓
找到可信来源 → 标注"数据无来源，但联网验证通过" → P1
  ↓
找不到来源 → P0阻断 — "数据无法验证，请删除或提供来源"
```

### 2.2 撞车检测（权重 25%）

| 结果 | 严重度 | 处理 |
|------|--------|------|
| 标题+核心论点无相似内容 | 通过 | — |
| 标题与平台热文高度相似（正文结构不同） | P1 | 建议修改标题 |
| 标题+论点+结构与已有内容高度一致 | P0 | 阻断，要求重写 |
| 部分论点与竞品雷同 | P1 | 标注雷同部分，建议重组 |

**撞车搜索方法**：

```
1. 取标题前 10 字作为搜索关键词
2. 取核心论点关键词
3. 用 group:web 分别在百度/必应搜索
4. 对比搜索结果的标题/摘要
5. 如果 2+ 结果高度相似 → 标记 P0/P1
```

### 2.3 平台合规（权重 25%）

从 `memory_read` 获取平台规则后逐项检查：

| 平台 | 检查项 | 严重度 |
|------|--------|--------|
| 所有平台 | 字数是否在限制范围内 | P1（超 20% 以内）/ P0（超 50%） |
| 所有平台 | 敏感词（违禁词、夸大词、限流词） | P0 |
| 所有平台 | 外部链接是否合规 | P1 |
| 小红书 | emoji 使用是否过度 | P2 |
| 小红书 | 标签数量（5-10 个） | P1 |
| 知乎 | 引用是否可点击 | P1 |
| 知乎 | 折叠规范 | P2 |
| 技术博客 | 论文引用格式 | P1 |
| 企业文档 | 保密标记、审批链 | P0 |

### 2.4 写作质量（权重 15%）

| 检查项 | 严重度 | 说明 |
|--------|--------|------|
| 风格 DNA 硬规则违规 | P0 | HOT 层规则被违反（禁用词出现、句长不匹配） |
| 结构不清晰 | P2 | 缺少逻辑主线 |
| 节奏问题 | P2 | 段落过于均匀，缺少变化 |
| AI 痕迹明显 | P1 | 填充短语、公式化结构、AI 词汇 |
| 跑题 | P1 | 正文与 topic_brief 核心观点不一致 |

## 评分标准

| 维度 | 权重 | 10 分标准 | P0 触发条件 |
|------|------|----------|------------|
| 事实准确性 | 35% | 所有数据可溯源至 research_notes，无错用无误解 | 关键数据错误或凭空编造 |
| 原创性 | 25% | 标题/论点/结构与平台热文无明显雷同 | 直接复制他人内容 |
| 平台合规 | 25% | 无敏感词、无违规引用、符合字数限制 | 含明确违规词/超字数红线 |
| 写作质量 | 15% | 结构清晰、逻辑流畅、风格 DNA 合规 | 风格 DNA 硬规则被严重违反 |

### 通过条件

```
总分 ≥ 7.0 且 无 P0 违规 → 通过
总分 ≥ 7.0 但 有 P0 违规 → 不通过
总分 < 7.0 → 不通过（即使无 P0）
总分 ≥ 7.0 且 无 P0 但有 P1 → 有条件通过
```

## Step 3 — 输出报告

### 输出格式（review_feedback）

```
## 审核报告
### 结果：{通过/有条件通过/不通过}

### 各维度评分
| 维度 | 得分 | 权重 | 加权分 |
|------|------|------|-------|
| 事实准确性 | 8/10 | 35% | 2.80 |
| 原创性 | 7/10 | 25% | 1.75 |
| 平台合规 | 10/10 | 25% | 2.50 |
| 写作质量 | 9/10 | 15% | 1.35 |
| 总分 | — | — | 8.40 |

### 需要修改
1. [P0] {必须修改的内容} → {建议方案}
2. [P1] {建议修改的内容}
3. [P2] {参考性建议}

### 修改历史（本次检查 vs 上次对比）
- 上次的 P0 "数据来源未标注" → 已修复 ✓
- 上次的 P1 "标题太像竞品" → 未修复 ⚠

### 微小建议（add_remark）
- {不写进 feedback 但值得一提的观察}
```

### 提交

`pipeline_write_slot('review_feedback')`。

如果结果不是"不通过"，pipeline 自动 advance 到下一 stage。
如果结果是"不通过"，pipeline 停在 review stage，等待 content-writer 修改。

---

## Step 4 — 重审

### 触发条件

content-writer 修改 `draft_content` → pipeline 重新 advance 到 review stage。

### 重审规则

| 规则 | 说明 |
|------|------|
| 只审未修复项 | 上次标记为 P0/P1 的项是重点 |
| 已修复的项标记 ✓ | 确认修复后不再跟踪 |
| 未修复的项升级警告 | 同个问题连续 2 次未修 → P0 升级为"严重" |
| 不重新审已通过项 | 原得分 ≥ 7 的维度不重新打分 |
| 全部 P0 修复后自动放行 | 无需人工确认 |

### 重审报告格式

```
### 修改历史（本次检查 vs 上次对比）
- 上次的 P0 "数据来源未标注" → 已修复 ✓
- 上次的 P1 "标题太像竞品" → 未修复 ⚠（升级为 P0 严重）
- 新增 P2 "第三段节奏偏慢" → 建议缩短

### 结果：{通过/有条件通过/不通过}
```

## 记忆工具使用模式

| 时机 | 工具 | 用途 |
|------|------|------|
| 审核前 | `snapshot_read` | 了解当前系统知识状态 |
| 审核前 | `session_note_read` | 读 content-writer 的自述笔记 |
| 审核前 | `session_search(keyword=选题)` | 查历史同类审核记录 |
| 审核中 | `group:web` | 事实交叉验证 + 撞车检测 |
| 审核后 | `memory_write(category="insight")` | 记录常见问题，下次改进 |

---

## 异常处理

| 场景 | 处理 |
|------|------|
| research_notes 不存在或为空 | 仍按文本审，事实核查标注"无原始调研数据可对比" |
| 联网搜索全部失败 | 撞车检测和事实验证降级为纯文本审查，标注"联网未验证" |
| 用户要求跳过审核 | pipeline 跳过此 stage，用户确认时记录 `memory_write("qa_skip_reason")` |
| 用户不认可审核结果 | 不争论，标注"已通知用户后仍坚持发布"，放行 |
| 风格 DNA 与平台规则冲突 | 以风格 DNA 优先，标注"风格 DNA > 平台默认建议" |
| 审核结果被用户反复驳回 | 标注"用户与审核存在分歧"，放行，记录到知识库 |
| content-writer 连续 3 次不修复同一 P0 | 升级为"严重"，通知 orchestrator/human 介入 |
