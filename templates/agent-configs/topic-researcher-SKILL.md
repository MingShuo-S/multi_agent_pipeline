# topic-researcher · SKILL

> 详细工作流：从对话开始到输出 topic_brief + research_notes

---

## 流程概览

```
用户输入（选题想法/需求描述）
  ↓
[Step 1] 对话出题 —— 确定选题方向、用户画像、平台调性
  ↓
[Step 2] 场景分类 —— 企业知识库 / 小红书 / 技术科普
  ↓
[Step 3] 多源搜索 —— 按场景路由到不同数据源
  ↓
[Step 4] 深度下钻 —— 不够就再搜，够了就停
  ↓
[Step 5] 输出 topic_brief —— 选题简报（场景自适应模板）
  ↓
[Step 6] 输出 research_notes —— 调研笔记（每项带置信度+来源）
  ↓
等待用户确认 → advance 或 继续调研
```

---

## Step 1: 对话出题

### 必须收集的信息

| 信息 | 获取方式 | 不能略过的条件 |
|------|---------|---------------|
| 选题方向 | 直接问用户"想写什么话题" | 至少问一次，不能假设 |
| 目标受众 | "写出来给谁看的" | 用户说"随便"时默认为"大众读者" |
| 平台 | "发在哪个平台" | 企业 KB / 小红书 / 知乎 / 公众号 / 技术博客 |
| 写作目的 | "这篇想达到什么效果" | 涨粉 / 记录知识 / 内部培训 / 个人品牌 |
| 参考素材 | "有没有什么想参考的文章或资料" | 用户回答"没有"则跳过 |

### 不出题的场景

如果用户直接给出了完整选题（如"帮我写一篇关于 Transformer 的科普文"），不需要对话出题，直接进入 Step 2。但必须在 topic_brief 中标注"用户已锁定选题，未走出题对话"。

### 用户画像获取

1. `memory_read`（旧名 kb_read）查知识库中是否已有该用户的画像
2. 如果没有，在对话中间接收集：经验等级（新手/进阶/专家）、身份（学生/职场/创业/自由职业）
3. 写回 `topic_brief` 的用户画像快照字段

---

## Step 2: 场景分类

读完 `target_audience` 中的场景字段后，确定搜索策略：

| 场景 | 搜索策略 | 数据源优先级 | 校准要求 |
|------|---------|-------------|---------|
| `enterprise` | 内部优先 | internal KB > 企业内部文档 > 行业报告 > web | 高（内部一致性） |
| `social` | 热点优先 | 平台热搜 > 竞品内容 > web 资料 | 中（趋势敏感） |
| `tech` | 深度优先 | 论文 > 技术文档 > 专业技术社区 > web | 最高（每句可溯源） |

如果场景字段为空或未知：
1. 从 `article_idea` 和对话内容推断
2. 推断不了就问用户"这篇是发在哪里的"
3. 写回 `target_audience`

---

## Step 3: 多源搜索

### 通用搜索流程

每次搜索必须遵守以下步骤：

```
1. 确定搜索关键词（从对话中提取 2-3 个关键词组合）
2. 按场景路由到对应数据源
3. 执行搜索
4. 检查结果质量——如果有 0 条或全部低质量，换关键词重试
5. 提取核心信息 + 保存来源 URL
6. 标记置信度
```

### 搜索路由表

| 场景 | 首选工具 | 备选工具 | 失败处理 |
|------|---------|---------|---------|
| enterprise | `kb_search` (lark-wiki) | `drive_search` (lark-drive) + `web_search` | 报告内部无相关内容 |
| social | `multi-search-engine` + `trend-analysis` | `web_search` | 报告趋势数据不可得 |
| tech | `search-academic` (arXiv/GScholar) | `web_search` + `webfetch` | 报告无可靠学术来源 |

### 搜索质量检查

执行搜索后，检查结果：

| 条件 | 行动 |
|------|------|
| 0 条结果 | 换 2 组关键词重试，仍无结果则标记"未找到" |
| 全部低质量（无来源/不可信） | 标记置信度"低"，如实报告 |
| 结果互相矛盾 | 保留双方观点 + 各标注置信度 + 建议用户自行判断 |
| 结果充分（3+ 条高置信度） | 汇总到 research_notes，进入 Step 4 |

### 跨源交叉验证（技术/企业场景 P0）

对于技术/企业场景的 P0 级别信息：

```
1. 找到至少 2 个独立来源支持同一结论
2. 如果来源冲突，记录双方观点
3. 只有 1 个可信来源 → 置信度标 "中"
4. 0 个可信来源 → 置信度标 "低" + 标注"待用户确认"
```

---

## Step 4: 深度下钻

### 触发条件

满足以下任一条件时触发深度搜索：

- 信息不足以支撑写一篇完整文章（"只有一段话能写"）
- 关键数据只有一个来源
- 用户主动要求"再深挖一下"
- 技术场景：论文只读了摘要，需要读全文

### 下钻方法

```
原始结果 → 找出关键疑问（"这个结论的实验样本量是多少"）
    ↓
生成新的搜索关键词（"样本量 + 实验条件"）
    ↓
从 target source 重新搜索
    ↓
如果有新发现 → 追加到 research_notes
    ↓
如果仍不够 → 问用户"这个方向挖不下去了，要不要换个角度"
```

### 终止条件

- 已获得充足的多源证据 → 停止
- 尝试 3 轮下钻后仍无新发现 → 停止 + 报告极限
- 用户说"够了" → 停止

## Step 5: 输出 topic_brief

根据场景选择模板：

### 企业知识库模板

```
## 选题简报
### 标题
{一句话标题}
### 目标受众
{部门/角色/经验等级}
### 知识盲区判断
- 当前 KB 中相关内容：{已存在/部分存在/不存在}
- 补全优先级：{高/中/低}（基于使用频率或管理层要求）
### 定位
- 文档类型：{规范/教程/FAQ/参考手册}
- 预期篇幅：{字数范围}
- 关联文档：{已有相关文档的链接}
### 参考来源
- {内部文档/行业标准的引用}
```

### 小红书创作模板

```
## 选题简报
### 标题
{一句话标题}
### 目标受众
{身份标签 + 核心痛点}
### 热点判断
- 趋势状态：{上升期/饱和期/冷淡期}
- 同类型内容数量：{多/中/少}
- 差异化切入点：{...}
### 核心信息
- 核心观点：{一句话}
- 预期长度：{字数范围}
- 内容形式：{教程/测评/故事/清单/观点}
### 参考来源
- {参考文章或素材的链接}
```

### 技术科普模板

```
## 选题简报
### 标题
{一句话标题}
### 目标受众
{读者水平：入门/进阶/专家}
### 技术定位
- 所属领域：{...}
- 前置知识要求：{...}
- 核心技术点：{要点列表}
### 写作建议
- 建议深度：{浅/中/深}
- 建议结构：{问题→原理→实践→总结 / 概念→类比→推导→应用}
- 难点：{需要尤其注意解释清楚的部分}
### 参考来源
- {论文/Spec/技术文档的引用}
```

---

## Step 6: 输出 research_notes

### 通用格式

```
## 调研笔记
### 验证结论
- {关键词} → {来源} → {结论} → {置信度: 高/中/低}
- {关键词} → {来源} → {结论} → {置信度: 高/中/低}
### 未解决的问题
- {问题描述} → {已尝试的搜索方向} → {卡点}
### 数据汇总
| 项目 | 数据 | 来源 | 置信度 |
|------|------|------|--------|
### 注意事项（对下游 Agent 的提示）
- {content-writer 需要注意的：如"这个数据只能引用结论不能引用方法"}
- {quality-reviewer 需要注意的：如"需要特别核实第 3 条数据"}
```

### 置信度规则

| 置信度 | 条件 |
|--------|------|
| 高 | 2+ 独立可信来源交叉验证通过 |
| 中 | 1 个可信来源 + 逻辑自洽 |
| 低 | 1 个来源但可信度一般 / 逻辑推断 / 无来源 |

**高置信度的信息 → quality-reviewer 可以做 P0 级别事实断言**
**中置信度的信息 → content-writer 可以引用但用词需保留余地**
**低置信度的信息 → content-writer 不应使用，除非用户明确要求**

---

## 用户确认

写完 topic_brief + research_notes 后，输出提示：

> "选题调研已完成。我已经整理了选题简报和调研笔记。
> - 如果你觉得方向没问题，说"继续"，我会把材料交给写作专家。
> - 如果你想再查点东西，告诉我想查什么。
> - 如果方向不对，告诉我怎么调整。"

用户关键词匹配：
- `["继续", "可以", "好的", "ok", "yes", "go", "没问题"]` → advance
- `["查", "搜一下", "看看", "找找", "再查"]` → 继续调研
- `["改", "不对", "换", "不是"]` → 调整方向，重新对话

## 记忆工具使用

| 工具 | 何时用 |
|------|--------|
| `session_search(keyword=..., slotName="topic_brief")` | 回顾同主题历史选题 |
| `session_search(agent="content-writer")` | 了解 content-writer 之前写了什么 |
| `snapshot_read` | 读冻结的 KB 快照，了解系统知识状态 |
| `session_note_read` | 读前序 Agent 的自述笔记 |
| `session_note_write("今天调研发现...")` | 记录调研洞察和策略观察 |

## 异常处理

| 异常 | 处理方式 |
|------|---------|
| 搜索工具全部不可用 | 基于已有知识 + 用户输入完成调研，标记"未经验证" |
| 用户目标含糊不清 | 提供 2-3 个方向选项让用户选择（比让用户从零描述更高效） |
| 搜索内容明显过时 | 标记"可能已过时" + 建议用户确认时效性 |
| 数据源访问受限 | 报告"受限"，建议用户提供替代来源或授权 |
